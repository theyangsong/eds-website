# Accessibility

EverGreen components follow WCAG 2.1 AA as the baseline target.

## Principles

1. **Perceivable** — sufficient color contrast, text alternatives for icons
2. **Operable** — keyboard navigable, visible focus states
3. **Understandable** — predictable behavior, clear labels
4. **Robust** — semantic HTML, ARIA only when needed

## Component checklist

### Button

- Uses native `<button>` element
- Supports `disabled` state
- Visible hover/focus states via CSS

### Icon

- Decorative icons use `aria-hidden="true"`
- Meaningful icons require `label` prop for accessible name

### Typography

- Semantic heading levels (`h1`–`h3`) via `variant` or `as` prop
- Sufficient contrast via theme tokens

## Testing

Storybook includes the **Accessibility** addon panel. Check each component story for violations before release.

## Color contrast

Theme tokens are designed for AA contrast in both light and dark modes. When adding new color combinations, verify contrast ratios in Figma or with browser DevTools.
